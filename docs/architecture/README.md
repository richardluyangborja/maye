# Architecture documentation

Architecture docs describe how Maye is built and how components interact. They should reflect implemented reality or clearly state proposed status.

Candidate documents, created only when useful:
- System overview and boundaries
- Repository/module structure
- Authentication and authorization
- Data model and migrations
- API conventions and contracts
- Media lifecycle and storage
- Notification lifecycle
- Security and privacy
- Mobile app architecture

Consequential choices belong in ADRs. Do not turn architecture docs into a second copy of product specs.
