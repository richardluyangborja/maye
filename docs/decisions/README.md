# Architecture decision records (ADRs)

Use ADRs for consequential, durable choices, including technology selection, architectural patterns, security-sensitive approaches, and decisions with meaningful trade-offs.

## Suggested format
1. Title and ID (e.g., ADR-0001)
2. Status: Proposed, Accepted, Superseded, or Rejected
3. Context and constraints
4. Options considered
5. Decision and rationale
6. Consequences, trade-offs, and risks
7. Follow-up actions / related docs

Do not create an ADR for every small implementation detail. An agent should not mark a proposed decision as accepted without appropriate task authorization or review. Keep ADRs immutable once accepted; supersede them with a new ADR.
