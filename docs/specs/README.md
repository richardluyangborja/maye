# Specifications

Feature specifications are delegated and developed before implementation when behavior is not sufficiently defined.

## Spec expectations
A feature spec should, as appropriate, include:
- Purpose, goals, non-goals and scope.
- Personas or user context and user stories.
- Flows and states.
- Functional requirements and testable acceptance criteria.
- Edge cases, failure paths, privacy and authorization requirements.
- Data needs and relationships.
- Notification, accessibility, and performance considerations.
- Dependencies, unresolved questions, and proposed slices.
- References to related ADRs and specs.

## Candidate spec areas
- Onboarding, identity, couple creation and invitations
- Memory creation, editing, viewing, reactions and comments
- Albums
- Timeline and relationship statistics
- Map view
- Recaps
- Celebration letters and reminders
- Question jars and answers
- Bucket lists
- Notifications and preferences
- Profile/settings, export and deletion

Specs should be linked and consolidated where sensible; do not create documents merely to match this list. Avoid duplicate requirements and keep scope aligned with v1 direction.
